# Precision Landing по ArUco — версия 2

Разбор проблем `pl_web_centered_light.py` и инструкция к новой реализации.
Код разложен по модулям в пакете [`pland/`](pland/), точка входа —
[`pl_web_centered_light_v2.py`](pl_web_centered_light_v2.py).

---

## 1. Быстрый старт

```bash
cd ~/pymavlink-scripts/src/cv

# 1) проверка математики (камера и полётник не нужны)
python3 pl_web_centered_light_v2.py --selftest

# 2) рабочий режим
python3 pl_web_centered_light_v2.py

# 3) то же, но с отладочным выводом вектора цели 5 раз в секунду
python3 pl_web_centered_light_v2.py --diag

# 4) проверка веба без железа (на ноутбуке)
python3 pl_web_centered_light_v2.py --no-camera --no-mavlink --port 8080
```

Веб: `http://<ip>:8080/` — страница с потоком и статусом, `/stream` — «сырой»
MJPEG, `/status` — JSON для скриптов.

Полезные ключи:

| Ключ | Смысл |
|---|---|
| `--url udpout:127.0.0.1:14551` | адрес MAVLink (по умолчанию как в старом скрипте) |
| `--port 8080` | порт веб-сервера |
| `--mount-yaw 270` | поворот камеры в корпусе, если поток «ведёт» не туда |
| `--no-mavlink` | не подключаться к полётнику |
| `--no-camera` | работать без камеры (проверка веба/сети) |
| `--diag` | печатать вектор цели и подсказку LEFT/RIGHT/FORWARD/BACK |
| `--selftest` | прогнать проверки геометрии и выйти |

Поток данных:

```
CameraSource.read() ──> ArucoTracker.process() ──> Target (углы в FRD)
                                   │                      │
                                   │                      └──> MavlinkNode.publish() ──> landing_target 20 Гц
                                   └──> Renderer.draw() ──> FrameHub.publish() ──> JPEG (1 раз) ──> N клиентов
```

Каждый модуль можно читать отдельно: `geometry.py` вообще не знает про камеру,
`web.py` — про детекцию, `tracker.py` — про сеть.

## 3. Что было не так и что изменено

### 3.1. Главное: смещения OFFSETS переводились в пиксели через высоту

Было:

```python
dx_m, dy_m = OFFSETS[active_id]
alt_eff = max(current_distance, 0.3)
u += (dx_m * fx) / alt_eff
v += (dy_m * fy) / alt_eff
angle_x = math.atan2((u - cx) / fx, 1.0)
angle_y = math.atan2((v - cy) / fy, 1.0)
```

Само по себе «смещение в пикселях» — это приближение, и оно ломается сразу в
четырёх местах:

1. **`alt_eff` — не высота над листом.** `current_distance` берётся из
   `LOCAL_POSITION_NED.z`, то есть от EKF-origin (точки взлёта), а не от
   площадки. Если origin не выставлен, z «плывёт» или равен нулю — включается
   зажим `0.3`, и поправка на 105 мм превращается в `0.105 * 1085 / 0.3 = 380 px`,
   то есть цель уезжает далеко за кадр.
2. **Масштаб `1/alt` растёт при снижении.** У земли поправка максимальна именно
   тогда, когда нужна точность: чем ниже дрон, тем сильнее команда «уйти в
   сторону», и метка выходит из кадра.
3. **Плоскость листа не параллельна матрице.** Крен/тангаж дрона и наклон
   площадки дают ошибку, которая ничем не компенсируется.
4. **Дисторсия не учитывалась.** У этого объектива `k1 = -0.42`, `k3 = -2.70`;
   при смещении на сотни пикселей от центра ошибка максимальна. Плюс лист мог
   быть повёрнут — смещение в пикселях тогда вообще едет не в ту сторону.

Числа в `OFFSETS` при этом правильные: они совпадают с раскладкой листа из PDF
(ID22 35 мм, ID33 70 мм справа, ID44 130 мм снизу). Проблема была не в числах,
а в способе их применения. В `config.py` оставлены ваши размеры печати
(34/67/126 мм) — если печатали PDF «как есть» и линейка показывает 35/70/130,
поправьте `marker_sizes` на пару процентов: от этого зависит масштаб позы.

**Стало** — смещение живёт в 3D:

```python
# поза найденной метки в системе камеры
ok, rvec, tvec = cv.solvePnP(obj_pts, img_pts, K, D, flags=cv.SOLVEPNP_IPPE_SQUARE)
R = cv.Rodrigues(rvec)[0]

# центр ID22 = центр метки + повёрнутое смещение
p_cam  = R @ (-dx, -dy, 0) + tvec
p_body = R_body_cam @ p_cam
angle_x = atan2(p_body.x, p_body.z)
angle_y = atan2(p_body.y, p_body.z)
```

Высота в формуле не участвует вообще, дисторсия учтена внутри `solvePnP`,
поворот листа — внутри `R`. Заодно появились проверки: ошибка репроекции
`< 5 px`, дальность `0.05…8 м`, угол `< 40°`, минимальный размер метки в
пикселях — «мусорные» детекции больше не командуют дроном.

### 3.2. Оси камеры и корпуса (вторая вероятная причина «улетел за лист»)

Старый код считал `angle_x` из координаты `u` (вправо по кадру), то есть молча
предполагал: **право кадра = нос дрона**. ArduPilot для `MAV_FRAME_BODY_FRD`
трактует `angle_x` как угол в плоскости X-Z (вперёд), `angle_y` — в плоскости
Y-Z (вправо). Если камера стоит иначе (а это самый частый случай), вектор
коррекции поворачивается на 90°: дрон уезжает в сторону и садится мимо листа,
сколько бы правильными ни были OFFSETS.

Теперь поворот камеры задан явно:

```python
mount_yaw_deg = 0    # 0 = верх кадра смотрит в нос
                     # 90 = вправо, 180 = в хвост, 270 = влево
```

`270` воспроизводит старую математику (право кадра = нос). Проверка занимает
две минуты — см. раздел 4, это обязательно нужно сделать один раз.

### 3.3. MAVLink: отправка только при найденной метке + гонка потоков

Было:

```python
if ids is not None:
    ...
    if tnow >= next_send_time:
        m.mav.landing_target_send(...)
```

То есть при потере метки сообщения прекращались совсем, и ArduPilot оставался
с последней (возможно, неверной) целью. Плюс `recv_match()` крутился в одном
потоке, а `landing_target_send()` вызывался из другого — обращение к одному
объекту pymavlink из двух потоков.

Стало: отдельный поток `MavlinkNode`, который и читает телеметрию, и отправляет
цель с фиксированной частотой 20 Гц. Если метка пропала — последняя цель
держится `target_hold_s = 0.3 с` и затем отправка прекращается (ArduPilot сам
поймёт, что данных нет). Главный цикл только кладёт цель в атомарный слот.

### 3.4. Почему «зависала отрисовка квадратов» в вебе

Три независимые причины, все воспроизводимые:

1. **`HTTPServer` был однопоточным.** Поток MJPEG бесконечный; если клиент
   перестал читать (обновили страницу, уснул ноутбук, пропал Wi-Fi), сервер
   оставался в этом обработчике и больше никого не обслуживал. На экране
   застывал последний кадр — ровно «как будто переполнился кэш».
2. **Каждый клиент копировал кадр (921 КБ) и кодировал JPEG заново.** Три
   вкладки — три кодирования каждые 50 мс, плюс мусор для GC.
3. **Исключение в главном цикле убивало детекцию, но не веб.** HTTP-поток был
   daemon и продолжал отдавать последний кадр вечно.

Стало: `ThreadingHTTPServer` + лимит `max_clients = 3` (четвёртый получает 503),
**один** общий JPEG-энкодер (кодирует только когда есть клиенты), таймауты
сокетов, ограниченный `SO_SNDBUF`, обрыв «мёртвого» потока через
`idle_close_s = 10 с` и автопереподключение на странице (`img.onerror`).
Кадры не копятся: клиент всегда получает последний.

Проверено локально: 3 клиента получают поток, 4-й — 503, после обрыва
соединения «в лоб» (RST) сервер продолжает обслуживать новые подключения,
счётчик клиентов корректно возвращается к нулю.

### 3.5. Мелочи, которые тоже стреляли

| Было | Чем плохо | Стало |
|---|---|---|
| `time.time()` для расписания | NTP-скачок на Pi без RTC → пауза в отправке или спам | `time.monotonic()` |
| `RGB888` + `cvtColor` | 921 КБ копии и конверсия на каждый кадр | `YUV420`, детекция по Y-плоскости |
| `while not check_connection(m):` | без полётника скрипт не стартовал вообще (и веб тоже) | подключение в фоне, веб работает сразу |
| нет `try/except` в главном цикле | одно исключение — и поток навсегда замирал | переоткрытие камеры, watchdog |
| `"calibration/camera.yaml"` | зависит от текущего каталога | путь от `__file__` |
| нет реакции на смену разрешения | K от другого разрешения | K масштабируется автоматически |
| `USE_FULL_POSE` не проверялся | `position_valid=1` без валидации позы | проверка репроекции + углов |

## 4. Проверка осей камеры (2 минуты, без винтов)

Это единственная настройка, которую нельзя угадать по коду.

1. Разложите лист, поставьте дрон сверху, метка **22** — в центре кадра,
   высота ~1 м, дрон стоит ровно.
2. Запустите `python3 pl_web_centered_light_v2.py --diag`.
3. Сдвиньте дрон на **20 см в сторону носа**, не меняя высоту и курс.
4. В консоли должно быть:

```
[DIAG] id=22 reproj=0.8px body=(+0.20,+0.00,1.00) ax=+0.20 ay=+0.00 -> target: FORWARD 0.20 m
```

Если вместо `FORWARD` появляется `RIGHT`, `LEFT` или `BACK` — камера
смонтирована с поворотом. Подберите `mount_yaw_deg` в `pland/config.py`:

| Что показывает `--diag` при сдвиге к носу | `mount_yaw_deg` |
|---|---|
| `FORWARD` | `0` (верх кадра смотрит в нос) |
| `RIGHT` | `90` |
| `BACK` | `180` |
| `LEFT` | `270` (поведение старого скрипта) |

Быстрая проверка без правки файла: `--mount-yaw 90`.

Если направление верное, но знак обратный (например, `FORWARD`, когда сдвинули
к хвосту) — лист перевёрнут или смотрит «вниз»; проверьте, что он лежит лицом
вверх, как напечатан.

В вебе в правом нижнем углу холста есть «компас»: стрелка `F` показывает, куда
в кадре смотрит нос. Это та же проверка, но глазами.

## 5. Настройки

Всё в [`pland/config.py`](pland/config.py), класс `Config`. Значения по
умолчанию соответствуют вашей конфигурации.

### Камера и метки

| Параметр | По умолч. | Смысл |
|---|---|---|
| `frame_size` | `(640, 480)` | разрешение; K масштабируется автоматически |
| `capture_fps` | `20` | частота камеры; должна совпадать с реальной скоростью цикла, иначе растёт задержка |
| `calib_path` | `calibration/camera.yaml` | путь считается от пакета, не от CWD |
| `af_mode` | `"off"` | `off` / `continuous` / `manual` |
| `lens_position` | `1.5` | диоптрии для `manual`: 1.5 ≈ 0.67 м, 3.0 ≈ 0.33 м |
| `marker_sizes` | `{22:0.034, 33:0.067, 44:0.126}` | реальные размеры печати в метрах |
| `offsets` | см. файл | смещение центра метки от ID22, +y вверх по листу |
| `priority` | `(22, 33, 44)` | кого считать целью первым |
| `min_marker_px` | `10` | метка мельче — игнорируется |
| `max_reproj_px` | `5.0` | отбраковка «кривой» позы |

### Монтаж и логика

| Параметр | По умолч. | Смысл |
|---|---|---|
| `mount_yaw_deg` | `0` | 0/90/180/270 — куда смотрит верх кадра |
| `mount_pitch_deg`, `mount_roll_deg` | `0` | если камера стоит с наклоном |
| `smooth_alpha` | `0.35` | EMA по вектору цели; `1.0` — без сглаживания |
| `jump_reset_m` | `0.25` | скачок больше — сброс фильтра |
| `target_hold_s` | `0.30` | сколько держим последнюю цель |
| `max_angle_rad` | `0.70` | защита от ложных детекций (~40°) |
| `use_full_pose` | `False` | `True` — отправлять x/y/z с `position_valid=1` |
| `send_distance` | `False` | `True` — отдавать дальность из позы |

### MAVLink и веб

| Параметр | По умолч. | Смысл |
|---|---|---|
| `mav_url` | `udpout:127.0.0.1:14551` | как в старом скрипте |
| `send_hz` | `20` | частота `landing_target` |
| `link_timeout_s` | `8` | нет сообщений — переподключение |
| `http_port` | `8080` | веб |
| `stream_fps` | `10` | частота кадров в веб (не детекции) |
| `jpeg_quality` | `60` | качество JPEG |
| `max_clients` | `3` | больше — 503 |
| `watchdog_s` | `8` | главный цикл не отвечает — аварийный выход |

**Добавить четвёртую метку** — две строки: `marker_sizes[55] = 0.20` и
`offsets[55] = (0.0, -0.25)`, затем `priority = (22, 33, 44, 55)`. Номер метки
при этом должен быть в словаре `DICT_4X4_50` (0…49) — для ID 55 возьмите
другой словарь, например `DICT_4X4_100`.

## 6. Диагностика

* `--diag` — строка 5 Гц:

  ```
  [DIAG] id=33 reproj=1.2px body=(+0.04,-0.11,1.32) ax=+0.03 ay=-0.08 -> target: LEFT 0.11 m
  ```

* `/status` — то же в JSON: `fps`, `marker`, `angle_x/y`, `alt`, `link`,
  `clients`, `errors`, `last_error`. Удобно вешать на мониторинг.
* Консоль: `[LOCK]` 2 Гц, `[MAV]` при переподключении, `[WATCHDOG]` при
  зависании, `[CALIB]` предупреждения о калибровке.
* Холст в вебе: контур метки, линия на цель, `F`/`R` — компас осей корпуса.

Если дрон «не видит» мелкую метку на снижении — почти всегда фокус: у
фиксированного объектива на 0.3–0.5 м картинка мыльная. Попробуйте
`af_mode="manual"` и `lens_position=2.0…3.0`, либо `continuous`.

## 7. Производительность на Pi Zero 2 W

| Что | Было | Стало |
|---|---|---|
| кадр | RGB888 921 КБ + `cvtColor` | YUV420, Y-плоскость 307 КБ, без конверсии |
| JPEG | на каждого клиента, 20 Гц | один раз, 10 Гц, только при наличии клиентов |
| копирование кадра | `latest_frame.copy()` на клиента | ссылка, без копии |
| HTTP | 1 поток | поток на клиента, лимит 3 |
| разбор кадра | параметры детектора по умолчанию | узкое адаптивное окно, `minMarkerPerimeterRate=0.02` |

Ориентир: детекция 640×480 на Zero 2 W — 20–40 мс, то есть 25–50 Гц в теории;
на практике цикл упирается в 15–20 Гц. Если хочется быстрее — `detect_scale=0.75`
(но мелкая метка 34 мм на 2 м станет 13 px и может пропасть).

## 8. Чек-лист перед полётом

1. `--selftest` проходит.
2. `--diag`: сдвиг к носу даёт `FORWARD`, к правому борту — `RIGHT`.
3. Метка 22 уверенно ловится с высоты ~1 м (в `--diag` `reproj` < 2 px).
4. В `[CALIB]` `cx`, `cy` близки к центру кадра (320, 240). Если нет —
   перекалибруйте на этом разрешении: смещённый principal point даёт
   систематический промах.
5. В вебе видны все три метки и линия на цель.
6. Проверить, что при пропадании метки отправка прекращается через 0.3 с
   (в логе `[LOCK]` исчезает, дрон переходит на обычную посадку).
7. Взлёт с листа: дрон должен «зависнуть» над меткой 22, а не над 33/44.

## 9. Запуск как служба

`/etc/systemd/system/pland.service`:

```ini
[Unit]
Description=Precision landing (ArUco)
After=network-online.target

[Service]
Type=simple
User=pi
WorkingDirectory=/home/pi/pymavlink-scripts/src/cv
ExecStart=/usr/bin/python3 /home/pi/pymavlink-scripts/src/cv/pl_web_centered_light_v2.py
Restart=always
RestartSec=2

[Install]
WantedBy=multi-user.target
```

Watchdog завершает процесс кодом 3, `Restart=always` поднимает его заново —
это надёжнее, чем пытаться оживить зависший поток из Python.

## 10. Ограничения

* Углы считаются для камеры, жёстко закреплённой на корпусе. Подвес/компенсация
  крена не поддерживаются (для посадки это и не нужно — ArduPilot сам
  стабилизирует).
* `landing_target` отправляется в `BODY_FRD` с `position_valid=0`; режим
  `use_full_pose=True` реализован, но на реальном полётнике не проверялся.
* Смещения заданы в системе листа. Если лист перевернуть, смещения нужно
  пересчитать (поменять знаки).
* Автофокус на снижении может «рыскать»; по умолчанию выключен.
