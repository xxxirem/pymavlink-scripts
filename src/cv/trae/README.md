# pl_web_centered_light_trae.py

Точная посадка дрона по ArUco-меткам через камеру Raspberry Pi. Скрипт детектирует
метки, вычисляет положение цели и отдаёт его полётнику в MAVLink (`LANDING_TARGET`),
параллельно показывая отладочный видеопоток в браузере.

## Запуск

```bash
cd src/cv/trae
python3 pl_web_centered_light_trae.py
```

Нужны: `picamera2` + `libcamera`, `opencv-contrib-python` (модуль `aruco`), `pymavlink`,
`numpy`. Файл калибровки — `src/cv/calibration/camera.yaml` (берётся на уровень выше папки `trae`).

## Веб-интерфейс

| Адрес | Назначение |
|-------|------------|
| `http://<ip>:8080/` | HTML-страница, поток сам переподключается при обрыве |
| `http://<ip>:8080/stream` (или `/video.mjpg`) | чистый MJPEG для VLC/ffmpeg |

Сервер многопоточный (`ThreadingHTTPServer`), JPEG кодируется один раз на всех клиентов
и только когда есть подключения. При отсутствии новых кадров соединение закрывается и
страница переподключается автоматически — ручной перезагрузки (F5) не требуется.

## Что делает

1. Снимает кадр с камеры (вниз, 640×480) и ищет ArUco-метки.
2. Выбирает цель по приоритету: `22 → 33 → 44` (34 / 67 / 126 мм).
3. Считает позу метки через `solvePnP`, переносит центр метки в центр **ID 22**
   (учёт смещения меток 33/44 по листу) и переводит вектор в систему корпуса.
4. Отправляет `LANDING_TARGET` с частотой 20 Гц (углы `angle_x`/`angle_y`, при
   `USE_FULL_POSE=True` — ещё и `xyz` с `position_valid=1`).
5. Рисует прицел оптической оси и точку цели на холсте и раздаёт его как MJPEG.

## Ключевые настройки (в начале файла)

- `MOUNT_YAW_DEG` — поворот камеры вокруг оптической оси относительно носа:
  `0` = верх кадра смотрит в нос, `90` = вправо, `180` = в хвост, `270` = влево.
- `USE_FULL_POSE` — `False`: только углы; `True`: полный xyz + `position_valid`.
- `SERIAL_IP` — подключение к полётнику (`udpout:127.0.0.1:14551`).
- `OFFSETS` — положение центров меток 33/44 относительно центра ID 22 (м), +y вверх по листу.
- `SEND_HZ`, `TARGET_HOLD_S` — частота отправки и удержание последней цели при пропадании метки.
- `STREAM_FPS`, `JPEG_QUALITY`, `MAX_CLIENTS` — параметры веб-потока.

## Системы координат

- **Камера (OpenCV):** +x вправо по кадру, +y вниз по кадру, +z вдоль объектива (вниз).
- **Корпус (FRD):** +x вперёд (нос), +y вправо, +z вниз.

Перевод задаётся матрицей `R_BODY_CAM`. Отправляемые углы: `angle_x = atan2(вперёд, вниз)`
(плоскость X-Z), `angle_y = atan2(вправо, вниз)` (плоскость Y-Z) — как ждёт ArduPilot
для `MAV_FRAME_BODY_FRD`.

## Отличия от `pl_web_centered_light.py`

- Многопоточный веб-сервер + единое кодирование JPEG → поток больше не зависает.
- Координаты: явная матрица монтажа камеры вместо неявного «право кадра = нос».
- Смещение меток к центру ID 22 считается в 3D с правильным знаком (было — деление
  на высоту EKF с инвертированным знаком).
- MAVLink читается и пишется из одного потока (`pymavlink` не потокобезопасен),
  `landing_target` шлётся постоянно, а не только пока видна метка.
- Перед ожиданием heartbeat скрипт сам анонсирует себя heartbeat'ом: для `udpout`
  это обязательно — pymavlink ничего не отправляет до первого `*_send`, и узел
  (mavlink-router/MAVProxy) не узнаёт наш адрес и не отвечает.
- `size_x/size_y` передаются в радианах (по спецификации MAVLink), а не в метрах.
